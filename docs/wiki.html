Auth flow

websupabase

  • Supabase SSR auth — cookies set server-side via @supabase/ssr
  • Login: /login → email/password or OAuth (Google, Outlook, Meta)
  • Register: /register → creates user + shows AVG consent before CV upload
  • Server actions in web/src/app/actions/auth.ts
  • Route protection: web/src/lib/supabase/server.ts createClient() in server components
  • Email redirect URL is derived dynamically from request.headers.get('host') — works on localhost, preview deploys, and production without hardcoding

AVG / GDPR

supabasebackend

  • Explicit consent gate before any CV upload
  • EU servers only — Supabase EU West, Railway EU. The AVG consent modal and privacy page no longer name a specific server city (Frankfurt was removed 2026-06-16) — users are directed to contact us for specifics
  • CV retention: user-defined 7 / 30 / 90 days (default 30). Auto-deleted on expiry
  • 7-day warning email before auto-delete (Supabase Edge Function + cron)
  • Account delete: wipes all data including CV and application history
  • No data used for AI training, no sharing with third parties

CV upload

websupabase

  • Route: /dashboard/profile — CV upload section with AVG consent modal shown before any file is accepted
  • AVG consent modal blocks upload until user explicitly accepts; stores consent timestamp in Supabase
  • Accepted formats: PDF, DOCX. Stored in Supabase Storage EU bucket (encrypted)
  • Retention period set at upload time: 7 / 30 / 90 days (default 30). User can change or delete at any time from profile settings
  • If no CV is uploaded, profile page shows a link to cvmaker.nl (external) — helps users without an existing CV create one before uploading (#61)
  • Key files: web/src/app/dashboard/profiel/page.tsx (page + CVUploadModal component)
AVG rule: The consent modal must appear before the file picker opens, not after — confirmed in avg-checker review (PR #58).

Vercel project setup

web

  • Two Vercel projects exist: opstap-app (active, production) and a legacy project — only opstap-app deploys opstapapp.nl
  • Root Directory must be set to web/ (not repo root) — the Next.js app lives in web/, not at the root
  • Framework Preset must be "Next.js" — "Other" causes build to fail silently
  • Site was down on 2026-06-13 because Root Directory was set to opstap (Flutter dir) and Framework was "Other" — both corrected via Vercel API
  • Required env vars on opstap-app: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, NEXT_PUBLIC_API_URL, ADMIN_API_KEY, NEXT_PUBLIC_TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, NEXT_PUBLIC_PLAUSIBLE_DOMAIN, SENDGRID_API_KEY, MOLLIE_API_KEY
  • First three were added 2026-06-13; remaining four still need to be set
Gotcha: Vercel caches the framework setting aggressively — after changing Framework Preset, trigger a manual redeploy (not just a git push) to pick up the change immediately.

Async email sender

backend

  • Key files: backend/app/services/email_sender.py, backend/app/services/email_notifications.py
  • All SendGrid HTTP calls are now wrapped in asyncio.get_event_loop().run_in_executor(None, ...) — prevents the FastAPI event loop from blocking during email delivery
  • Applies to: application confirmation emails, credit-warning emails, admin credit/suspension notifications, CV expiry warnings
  • Admin-triggered emails (credit adjustment, account suspension) send immediately on the admin action endpoint response cycle — non-blocking ensures the admin API responds quickly regardless of SendGrid latency
Gotcha: Do not pass coroutines into run_in_executor — it only accepts regular (sync) callables. Wrap the sync SendGrid SDK calls, not async wrappers around them.
