What is Opstap?

Dutch job application automation — slogan: "Meer kansen. Minder moeite."

Opstap automates the Dutch job application process. A user uploads their CV or fills in their profile manually, searches the major Dutch job boards, selects a job, and Opstap generates a personalised Dutch motivation letter using Claude AI — then sends the application by email or web form.

User flow (step by step)

  1. User visits opstapapp.nl → registers (email/password or Google OAuth)
  2. Confirms email via link → lands on dashboard
  3. Uploads CV (PDF) — AVG consent shown first → stored encrypted in Supabase Storage
  4. Searches vacatures by keyword + location on NL job boards
  5. Selects a job → dashboard shows job details
  6. Chooses writing style (Formeel / Informeel / Enthousiast) and send method (Email / Webformulier)
  7. Claude generates a Dutch motivation letter → user reviews & edits
  8. User confirms → application sent
  9. Application logged in "Jouw reacties" history

Request flow (apply)

Browser → Next.js (Vercel)
         → POST /api/v1/apply (Railway FastAPI)
              → Supabase (check user, load profile)
              → Claude API (generate motivation letter)
              → SendGrid (send email) OR Playwright (web form)
              → Supabase (log application)

Auth flow

Register → Supabase sends confirmation email
           → User clicks link → /auth/confirm?token=...
           → Supabase verifies OTP → session created
           → Redirect to /dashboard
EU-only rule: No personal data leaves the EU. Supabase is on Frankfurt servers. Railway uses EU West. Claude API receives only the CV content + job description — no names or contact details.

Claude API

Anthropic — model: claude-sonnet-4-6

How it's used

The FastAPI backend calls Claude to generate personalised Dutch motivation letters. The prompt includes: job title, company, job description, user's CV content (stripped of PII), and the user's chosen writing style.

Cost note: This is the main variable cost. Each letter generation uses ~1,000–3,000 tokens. At current pricing ~€0.003–0.01 per application. See monetization planning for how to handle this sustainably.

Where the key lives

In Railway env vars as ANTHROPIC_API_KEY. Never in the frontend or committed to git.

Retention

Users choose retention period at upload (7 / 30 / 90 days). A warning email is sent 7 days before expiry. CV is auto-deleted on expiry by the cleanup-expired-cvs Edge Function. User can delete manually at any time from the dashboard.

Auth Flows

Registration, login, password reset, social OAuth

Register

  1. POST to Supabase auth via server action (web/src/app/actions/auth.ts)
  2. Supabase sends confirmation email to user
  3. User lands on /register/bevestig (holding page)
  4. User clicks email link → /auth/confirm?token_hash=...&type=email
  5. OTP verified → session created → redirect to /dashboard

Google OAuth

  1. User clicks "Doorgaan met Google" (SocialButtons component)
  2. supabase.auth.signInWithOAuth({ provider: 'google' })
  3. Google redirect → Supabase callback → session → /dashboard

Password reset

  1. /forgot-password → user enters email
  2. Supabase sends reset email (enumeration-safe — always shows "sent")
  3. User clicks link → /auth/reset → /reset-password
  4. User sets new password → login

CV Upload

PDF upload → Supabase Storage (encrypted)

Flow

  1. User opens dashboard → clicks "CV uploaden"
  2. AVG consent modal appears (if not yet consented)
  3. User selects retention period (7 / 30 / 90 days) and accepts
  4. avg_consent_given_at stamped on profile
  5. PDF uploaded to cvs/{user_id}/{filename}.pdf in Supabase Storage
  6. cv_storage_path + cv_expires_at saved on profile

Job Search

Searches NL job boards via backend API

Sources

  • Adzuna NL (API) — aggregates Indeed NL, LinkedIn NL, Jobbird, Nationale Vacaturebank

Flow

  1. User enters keyword + location in dashboard search
  2. Frontend calls GET /api/v1/jobs?q=...&location=...
  3. Backend checks jobs_cache table first (TTL: 1 hour)
  4. If cache miss → calls Adzuna API → stores in cache → returns results
  5. Results displayed as cards with title, company, location, salary, description

Auto-Apply

Send application via email or web form

Email apply flow

  1. User selects job → chooses "E-mail" method
  2. Enters contact email address (validated server-side)
  3. Backend generates letter via Claude
  4. SendGrid sends email from sollicitaties@opstapapp.nl
  5. Application logged in applications table

Web form apply flow

  1. User selects job → chooses "Webformulier" method
  2. Backend uses Playwright to navigate to job URL
  3. Fills form with profile data + generated letter
  4. Submits form
  5. Application logged in applications table
Note: Web form apply works for simple forms. Complex forms with CAPTCHAs or custom portals may fail.

AI Motivation Letter

Generated by Claude (claude-sonnet-4-6) in Dutch

Inputs to the prompt

  • Job title, company name, job description
  • User's CV content (text extracted from PDF)
  • User's writing style preference (Formeel / Informeel / Enthousiast)
  • System prompt: "Write a professional Dutch motivation letter..."

What happens next

  1. Letter displayed to user in dashboard (editable textarea)
  2. User can edit before sending
  3. Letter is HTML-stripped server-side before storage (XSS protection)
  4. Stored in applications.letter_nl
Letters are always editable before sending — AVG Rule 7 (every automated decision visible and editable).

Deployments

How code gets to production

Web (Vercel)

  1. Push/merge to master on GitHub
  2. Vercel auto-deploys (GitHub integration)
  3. Build: cd web && npm run build
  4. Live at opstapapp.nl within ~2 minutes

Backend (Railway)

  1. Push/merge to master
  2. Railway auto-deploys (GitHub integration)
  3. Build: Docker via backend/Dockerfile
  4. Live at opstapapp-production.up.railway.app within ~3 minutes

Database migrations

  1. Write SQL in supabase/migrations/00X_name.sql
  2. Run npx supabase db push or use Supabase MCP apply_migration
  3. Migrations are idempotent and versioned
